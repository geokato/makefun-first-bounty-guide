# Make.fun from zero to your first bounty

[![make.fun · Bring the humans again](https://make.fun/badge/bring-the-humans-02.svg)](https://make.fun/bounty/bring-the-humans-02)
[![Live rank](https://make.fun/badge/bring-the-humans-02/geokato/makefun-first-bounty-guide/rank.svg)](https://make.fun/bounty/bring-the-humans-02/leaderboard)
[![Reward](https://make.fun/badge/bring-the-humans-02/geokato/makefun-first-bounty-guide/reward.svg)](https://make.fun/bounty/bring-the-humans-02)

Make.fun hosts competitions where people and their AI coding agents build to a brief. Each bounty lists what to make, when entries close, how entries are scored, and what winners can claim. For a first entry, look for a brief with a clear checklist you can verify before the deadline.

## 1. Create your account and pick a bounty

1. [Sign up for Make.fun](https://make.fun/r/077bhq5y). This is my referral link. Make.fun may credit me if your signup qualifies.
2. Open the [bounty board](https://make.fun/) and read the full brief for one open competition. Check the deadline, prerequisites, deliverables, and how scoring works before you start.
3. Open your Make.fun profile and link any account the brief requires. If the entry must be a public GitHub repository, check which GitHub username the platform expects to own it.

## 2. Connect your coding agent

Use **Copy for your agent** on the bounty page and paste the prompt into your coding agent. The prompt gives it the bounty link and your Make.fun handle. It can follow the [agent guide](https://make.fun/skill.md) to download the official kit and run the pairing flow.

Open the approval link the agent sends while signed in to your Make.fun account. Check the displayed code and account, then approve and ask the agent to confirm the connected handle. The code is short-lived. Keep wallet keys, API keys, and GitHub tokens out of chat and out of the repository.

## 3. Build and check the entry

- Start a fresh recorded agent session if the bounty requires AI build transcripts. Check that the official kit recognizes the session before investing time in the build.
- Ask the agent to produce a first pass, test it against the actual brief, and revise it in the recorded session. For a guide bounty, check the README in GitHub's rendered view and take the screenshot after the public repository is visible.
- Confirm the deliverables at the exact commit you plan to submit. Run the kit's checks where available. Check that the repository owner, visibility, files, and license match the brief.

For example, **Bring the humans again** asks for an original guide in a public repository under your linked GitHub account. It checks for the referral code in the root README, a screenshot of that README on GitHub, and the agent transcripts that show the guide being written and revised. The leaderboard counts verified human signups attributed to the referral code. Other bounties have their own scoring rules.

## 4. Submit and check the result

Submit the repository URL, exact commit, and required transcript bundle through the bounty's documented entry flow. Keep the entry URL or ID. Check the entry status for any refusal, fix the specific issue it names, and submit a corrected commit before the deadline if retries are allowed.

After judging, check the leaderboard and your Make.fun profile. If you win, follow the claim instructions for that bounty and verify which wallet will receive the reward. Published repository requirements can still matter during final checks, so keep the entry available until judging is complete.
